# keri-protocol

KERI protocol messages in Rust: key events, exchange and reply messages, the TEL registry
inception, self-addressing identifiers and prefixes, exact signing thresholds, deterministic
serialization, and CESR attachments. The behavior and wire bytes match
[signify-ts](https://github.com/WebOfTrust/signify-ts), checked against fixtures it generates;
the two attachment groups signify-ts cannot emit are checked against
[keripy](https://github.com/WebOfTrust/keripy) instead.

Extracted from the signify-rs project.

## Modules

| Module | Purpose |
|---|---|
| `serialization` | Protocol versions and version strings, the deterministic self-addressing-data (SAD) codec, and the message serializer and parser |
| `said` | Self-addressing identifiers: derive and verify |
| `prefix` | Identifier prefixes: derive and verify, with transferability |
| `threshold` | Exact numeric and weighted signing thresholds |
| `event` | Event kinds, the `icp`/`rot`/`ixn` builders and their delegated forms, `exn` and `rpy` messages, timestamps, witness fault tolerance, configuration traits |
| `attachment` | CESR attachments composed around a message: controller, witness and receipt signature groups, seals, pipelining |
| `stream` | Incoming message streams parsed back into events and typed attachment groups |
| `registry` | The TEL registry inception event (`vcp`) |

Everything here builds, serializes and verifies messages. Key management, the client's identity
and the KERIA agent model are not here; neither is KEL validation (accepting events into a log and
deriving key state), which a server would add on top.

Nothing in this crate reads a clock or a random source: timestamps and nonces are inputs, so every
message is reproducible.

## Use

```bash
cargo add keri-protocol
```

```rust
use keri_cesr::crypto::verifier::VerificationKey;
use keri_protocol::event::inception::InceptionBuilder;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let key = VerificationKey::from_qb64("DFs8BBx86uytIM0D2BhsE5rrqVIT8ef8mflpNceHo4XH")?;
    let event = InceptionBuilder::new(vec![key]).build()?;

    // One transferable key and no explicit derivation makes the key itself the identifier.
    assert_eq!(event.identifier().qb64()?, "DFs8BBx86uytIM0D2BhsE5rrqVIT8ef8mflpNceHo4XH");
    assert_eq!(event.sequence_number(), 0);
    assert!(event.raw().starts_with(br#"{"v":"KERI10JSON0000fd_","t":"icp""#));
    Ok(())
}
```

## Prerequisites

- Rust 1.97 or newer (`rustup` installs the toolchain pinned in `rust-toolchain.toml`).
- Nightly Rust and `cargo-fuzz`, only for fuzzing.
- Node 22 or newer, `uv`, and libsodium, only to regenerate the fixtures.

## Build and test

```bash
cargo fmt --all -- --check
cargo clippy --all-targets
cargo test
cargo deny check
```

## Reference fixtures

`fixtures/` holds the expected outputs. Ten groups are generated by signify-ts at the commit pinned
in `tools/reference-vectors/package.json`; `attachment-keripy` and `stream-keripy` are generated by
keripy at the commit pinned in `tools/reference-vectors/pyproject.toml` and locked in `uv.lock`. Tests read the fixtures
and never need Node, Python or the network. Each fixture directory has a README with its
provenance.

```bash
npm ci --prefix tools/reference-vectors
uv sync --locked --project tools/reference-vectors
npm run --prefix tools/reference-vectors check      # regenerate and fail if anything changed
npm run --prefix tools/reference-vectors generate   # regenerate after an intended change
```

The keripy generator needs libsodium at runtime (`libsodium23` on Debian and Ubuntu, `libsodium`
from Homebrew on macOS).
